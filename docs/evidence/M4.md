## Actual constraints / ownership

Memory 1 GiB (1073741824 bytes), 2 CPUs (2000000000 NanoCPUs), privileged false,
non-root uid/gid, network none, cap-drop ALL, no-new-privileges, pids limit 64,
64 MiB temporary tmpfs. No bind mounts, Docker socket mounts or secrets in the
container. One sandbox at a time, with process-global admission and an atomic
checkout-owned lock. Labels derive the same kit checkout hash and add kind
`audit-sandbox`; dead-owner recovery selects both labels, never unrelated resources.

Capture tails are 8 KiB/stream, default command timeout 10 s. Actual Docker state
supplies exit code. Timeout/abort are Incomplete, nonzero check Failed. Container
removal is verified on success, failure and interruption; cleanup failure cannot
return success. SIGTERM/SIGINT cancel audit/model work and clean clones. Startup
recovers dead-owner containers; unavailable Docker remains Incomplete, not PASS.

## Limits and reproducibility

Use `./ops/local-agent/scripts/build-sandbox.sh` once with >=20 GiB free disk.
Image is not downloaded/built automatically during audits; missing image fails
Incomplete. One container only, no Compose/cloud/engine stack.

Clone and API model stay in the backend; the copied repository check executes
in Docker. Writable disposable layer is necessary for Docker Desktop copy, not
host access. Only the M3 narrow safe policy is supported. README tracking is a
limited evidence check, not repository tests/security verification. M2 /analyze
is preserved. API calls, commands and Docker are not mocked in acceptance;
controlled local fixture programs are used only to exercise failure/timeout paths.
M5 master stage integration/reliability is not claimed by M4.
