## Real master acceptance

Target https://github.com/octocat/Hello-World. Actual browser submits the form,
actual web/API accept and poll progress, real GitHub clone, one real xkiro /
mistralai/ministral-8b model call, one real Docker container command, UI finding,
and automatic filesystem/container cleanup.

The model reviews bounded actual source BEFORE execution; the server attaches
actual output afterward. It does not pretend the model interpreted future output.
The executed command is the allowed limited README tracking check:

`git -c core.fsmonitor=false ls-files --error-unmatch -- README`

Actual exit 0, stdout `README\n`, stderr empty. Captured-output/exit SHA-256:
`dfa0f0939396cf84ba4acd61a3e26cf83a2eafd5b8970e718e712700197b467f`.
This is not a repository test suite or a verified security verdict.

- [Per-run JSON](m5-runs.json): ten consecutive full browser-driven live web/API
  runs, each with clone/model/sandbox/cleanup status, command/actual output/exit,
  output hash, real finding/severity, durations and observed host MemAvailable.
- Each run checks 429 Busy, both health endpoints, actual Docker limits/removal,
  absent cloned directory, empty registered-workspace root, rendered finding and

- API requests contain unique run identities and no-cache request headers;
  recorded provider response identities are distinct across the ten runs.
  Provider trace/usage/cache-header values are recorded, not invented.
  This makes repeated response replay detectable. Execution is never cached.

## Safety and recovery

1 GiB RAM, 2 CPUs, nonprivileged/non-root, network none, caps dropped,
no-new-privileges, pids 64, bounded tmpfs; no host mounts/socket/model credentials.
Actual limits are inspected. Clone copy uses a disposable writable layer,
explicitly not a read-only rootfs. Only M3's three narrow command policies run.

Command 10 s, model 60 s, clone 119 s, total master 120 s; cancellation and bounded
output (8 KiB/stream). Errors/capability gaps and failed master checks are
Incomplete with failed stage named. Docker exit 1 remains a real Failed execution
inside that Incomplete master result. Cleanup failures cannot return Completed.

Workspace ownership is persisted before mkdir beneath the checkout-owned state
root. SIGTERM/SIGINT cancel and clean; dead PID/start-identity clone registrations
and labelled sandbox containers recover on restart. Live owners are preserved;
unverified ownership is refused. Actual tests cover success, SyntaxError failure,
started-command timeout, Busy, abort, real HTTP interruption, unavailable model,
SIGKILL owner recovery, and different-state-root live-container preservation.
